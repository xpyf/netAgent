# 定义 JSON→图映射规则

Type: grilling
Status: resolved
Blocked by:

## Question

定义「JSON→图 映射规则」的精确语义，作为规格的核心章节：

- 如何判断一个 JSON 对象是「节点」「边」还是「边的属性」。
- 嵌套引用/链接字段如何变成边。
- 字段如何对齐实体属性与 `key_field`。
- 未知字段、缺失必填、类型不符 → 具体落成哪条告警/跳过规则。
- 需要一份**模拟生成的网络拓扑样例 JSON** 作为运转样例。

样例资产：`samples/topology-sample.json`（已在对话中确认）。

## Answer

映射规则主体（六条，全部经 grilling 确认）：

**A 实体类型判定**：能识别为某实体类型的对象才是节点。类型优先看 `kind` 字段（值 = node_type 名，`"kind":"router"`→Router）；无则退按所在数组键名映射（`networks→Network`）；识别不了走 F。

**B 嵌套结构**：取决于模型——模型有对应实体类型（如 Interface）则提升为节点并建边连回宿主；否则作为宿主属性存嵌套 JSON 值。

**C id 引用变边**：对象含可对应某实体类型 key_field 的引用字段（如 `a`/`z`→设备 id）→ 成边；边类型优先看 `type` 匹配 edge_type.name，缺省按所在键约定（`links→CONNECTED_TO`）；其余字段成边属性；引用不到实体走 F。

**D 字段对齐**：字段名 = 属性名直接同名匹配；`id` 对齐 key_field；模型未声明字段走 F。不设别名/驼峰转换。

**E 信封/元数据**：不匹配实体类型的包裹对象（如 `report`）不建节点；标量不入图，仅作日志上下文。

**F 异常规则**（四条，均告警+跳过、记日志）：

1. 无法归属实体类型的对象 → 跳过该对象。
2. 缺 key_field（无唯一身份）→ 跳过该节点/边。
3. 属性类型不符或未知字段 → 跳过该条属性（节点保留）。
4. 边引用了不存在的源/目标 id（悬空边）→ 跳过该边。
