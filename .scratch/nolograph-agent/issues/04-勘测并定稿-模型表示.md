# 勘测并定稿“模型表示”（pgsql 元数据表模式）

Type: grilling
Status: resolved
Blocked by:

## Question

勘测 pgsql 元数据表现状并定稿「模型表示」：

- 是否已有 pgsql 元数据表；若有，实际结构如何；若无，按规格草案
  `node_type(type_id, name, key_field)` / `node_attribute(type_id, attr_name, attr_type, optional, cardinality)` /
  `edge_type(edge_id, name, source_type, target_type)` / `edge_attribute(...)` 新定义。
- 表结构、属性类型字段、必填/基数、**可扩充机制**如何规范化进规格。

## Answer

**勘测记录（已完成）**：pgsql 现可达（5432，驱动经 uv 临时环境装入）。实测：**全新集群**——仅默认库 postgres/template0/template1，postgres 库内无任何用户表。**不存在「既有的模型元数据表」**，因此模型表示从草案新建，草案即事实源。

**模型表示（定稿）**：按规格草案（经 grilling 拍板）：

1. **表结构**（4 张）：
   - `node_type(type_id PK, name UNIQUE, key_field)`
   - `node_attribute(type_id FK→node_type, attr_name, attr_type, optional, cardinality)`，`PK(type_id, attr_name)`
   - `edge_type(edge_id PK, name UNIQUE, source_type FK→node_type, target_type FK→node_type)`
   - `edge_attribute(edge_id FK→edge_type, attr_name, attr_type, optional, cardinality)`，`PK(edge_id, attr_name)`
2. **属性类型词表**（8 种）：`text` / `int` / `float` / `bool` / `ip`(地址) / `cidr`(网段) / `datetime` / `json`(嵌套结构属性，承载映射规则 B 的「嵌套当属性」)。
3. **cardinality / optional 语义**：`cardinality`=标量还是列表（`scalar`/`list`），`list` 属性直接映射 JSON 数组；`optional`=可空（`true`/`false`）。
4. **可扩充机制**：纯增量的元数据行——加新实体类型/属性/边类型只需 INSERT 一行，不改代码；新增不破坏已有数据（新类型无旧节点，旧属性补 `optional=true`）。符合基线 Q11「不靠脏数据自动扩充」——扩充是有意的管理动作，非摄入时顺手。
5. **约束**：模型表自身用 FK + UNIQUE 保护（`outer_key` 引用必须存在、`name` 唯一），防止写出悬空类型。
6. **读取路径**：agent 不直接碰表，统一走 `load_model()`（工具契约 03），聚合查询返回结构化模型。

数据库名、schema 归属：实现阶段定义（`数据库你自己定义` → 由实现确定，如 `model_meta`）。
